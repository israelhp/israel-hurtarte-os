## Findings of the audit and what was done

1. **R1 was stale** (the audit saw 7 high advisories): two extra came from `serve` → `compression` (dev only). `serve` was replaced by a 60-line, dependency-free static server for local and CI runs; `npm audit` is back to the 5 known dev-only advisories (below).
2. **Header completeness**: added `upgrade-insecure-requests`, more Permissions-Policy features, COOP/CORP, `frame-src`/`manifest-src`/`worker-src`.
3. **Claude Code hook gaps** (`.claude/hooks/guard-bash.mjs`): the destructive-command guard missed split flags (`-r -f`), long flags (`--recursive --force`), `find -delete`, `git -C … reset --hard`, `git push -f` / `+ref` / `HEAD:main` and `curl | python|node`. Fixed, with 39 hook tests (was 17). It remains a safety net, not a security boundary (a shell can always obfuscate), as documented. The hardened guard blocked a command of mine that merely _mentioned_ one of those patterns, which confirms it works.
4. **CI supply chain**: SHA-pinned actions and Dependabot.

## Open items / accepted risks

- **`script-src 'unsafe-inline'`** (accepted, low). Needed by Next's inline bootstrap scripts, the pre-paint theme script and the `/` redirect. There is no user-generated HTML, no third-party script and no reflected input, so the practical exposure is small. A static export has no per-request nonce; a hash-based policy would need a post-build step that hashes every inline script in `out/**/*.html` into the header, and the hashes change on every build. Revisit if the site ever renders user content.
- **R1: 5 dev-only `npm audit` advisories** (`braces` → … → `eslint-config-next`: lint tooling, not shipped; the suggested fix downgrades `eslint-config-next` to v14). Unchanged.
- **Not testable locally**: the live Vercel headers (re-check with `curl -I` after the first deployment) and HSTS preload (needs a domain).
- **Third parties**: the references in the owner's original CV are not published (decision D12).
